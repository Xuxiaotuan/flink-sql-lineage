# 代码结构说明

## 1. Listener 入口

文件：

```text
src/main/java/com/hw/lineage/flink/listener/Flink21LineageListenerFactory.java
```

作用：

```text
实现 JobStatusChangedListenerFactory
创建 JobStatusChangedListener
监听 JobCreatedEvent
读取 LineageGraph
输出 JSONL 事件
```

ServiceLoader 文件：

```text
src/main/resources/META-INF/services/org.apache.flink.core.execution.JobStatusChangedListenerFactory
```

内容：

```text
com.hw.lineage.flink.listener.Flink21LineageListenerFactory
```

Flink 会靠这个文件发现插件。

## 2. schema 提取逻辑

优先级：

```text
1. LineageDataset.facets() 里的 DatasetSchemaFacet
2. TableLineageDataset.table() 反射拿 CatalogBaseTable
3. ResolvedCatalogBaseTable#getResolvedSchema()
4. CatalogBaseTable#getUnresolvedSchema()
```

这一步参考了 OpenLineage 的 `TableLineageDatasetWrapper` 思路。

## 3. 演示 Job

文件：

```text
src/main/java/com/hw/lineage/flink/listener/Flink21LineageDemoJob.java
```

作用：

```text
创建 listener_ods_user datagen 表
创建 listener_dwd_user blackhole 表
执行 INSERT INTO ... SELECT ...
触发 JobCreatedEvent
```

## 4. 回放脚本

文件：

```text
scripts/06_回放到血缘服务.py
```

作用：

```text
读取 Listener JSONL
把 inputs/outputs schema 转成 CREATE TABLE
调用 flink-sql-lineage 创建表
创建任务
写入 INSERT SQL
触发字段级血缘分析
```

注意：

`flink-sql-lineage` 的 `ddl` 和 `source` 字段都需要 Base64 编码，脚本已经处理。
