# 手动重现实验指南

## 1. 实验目标

这个实验验证一件事：

```text
Flink Listener 拿到 schema 后，可以让 flink-sql-lineage 重新跑 planner，生成字段级血缘。
```

不是让 Listener 直接生成最终字段级血缘。Listener 的职责是采集运行时信息；`flink-sql-lineage` 的职责是重放上下文并做字段级解析。

## 3. 编译 Listener

```bash
cd /Users/xujiawei/magic/workbench/flink-sql-lineage
lineage-flink2.1-listener/scripts/01_编译监听器.sh
```

产物：

```text
lineage-flink2.1-listener/target/lineage-flink2.1-listener-1.0.0.jar
```

这个 jar 里包含两类东西：

- `Flink21LineageListenerFactory`：Flink 全局 Listener 插件入口。
- `Flink21LineageDemoJob`：用于本地提交的演示 Flink SQL Job。

## 4. 安装到 Flink

```bash
lineage-flink2.1-listener/scripts/02_安装到Flink.sh
```

会复制到两个地方：

```text
~/software/flink/flink-2.1.0/plugins/flink21-lineage-listener/lineage-flink2.1-listener-1.0.0.jar
~/software/flink/flink-2.1.0/lib/flink21-lineage-listener.jar
```

为什么要放两份：

- `plugins`：给 Flink JobManager/TaskManager 插件加载用。
- `lib`：给 `flink run`、SQL Client 这类客户端进程也能找到 listener class。

## 5. 配置 Flink

```bash
lineage-flink2.1-listener/scripts/03_配置Flink.sh
```

脚本会备份 `config.yaml`，然后追加：

```yaml
execution.job-status-changed-listeners: com.hw.lineage.flink.listener.Flink21LineageListenerFactory
lineage.experiment.event-file: /tmp/flink21-lineage-events.jsonl
```

这两个配置的含义：

- `execution.job-status-changed-listeners`：告诉 Flink 加载哪个 ListenerFactory。
- `lineage.experiment.event-file`：告诉实验 listener 把事件写到哪里。

## 7. 提交演示任务

```bash

```

演示任务逻辑：

```text
listener_ods_user(datagen)
  -> SELECT id, UPPER(name), DATE_FORMAT(birthday), CAST(score)
  -> listener_dwd_user(blackhole)
```

```text

```

```json
{

  "outputs": []

```

## 8. 回放到 flink-sql-lineage

```bash
lineage-flink2.1-listener/scripts/06_回放到血缘服务.py
```

默认血缘服务地址是 `http://127.0.0.1:8194`，默认使用项目初始化账号 `admin/admin` 走 HTTP Basic 认证。你改过账号时这样传：

```bash
lineage-flink2.1-listener/scripts/06_回放到血缘服务.py --用户名 your_user --密码 your_password
```

脚本做了几件事：

1. 读取 `/tmp/flink21-lineage-events.jsonl` 最后一条事件。
2. 从 `inputs/outputs` 提取 schema。
3. 生成 `CREATE TABLE IF NOT EXISTS ... WITH (...)`。
4. 调用 `flink-sql-lineage` 的创建表接口。
5. 创建一个任务。
6. 把演示 `INSERT` SQL 写入任务。
7. 调用 `/tasks/{taskId}/lineage` 分析。

成功现象：

```text
taskStatus=SUCCESS
taskLog=
```

## 10. 常见问题

### ClassNotFoundException: Flink21LineageListenerFactory

说明客户端进程没有找到 listener jar。

处理：

```bash
lineage-flink2.1-listener/scripts/02_安装到Flink.sh
lineage-flink2.1-listener/scripts/08_停止Flink.sh
lineage-flink2.1-listener/scripts/04_启动Flink.sh
```

### 事件文件不存在

先检查 Flink 是否启动：

```bash
lsof -nP -iTCP:8081 -sTCP:LISTEN
```

再检查日志：

```bash
rg -n "lineage|JobStatusChanged|Flink21Lineage|ERROR|Exception" ~/software/flink/flink-2.1.0/log/*.log
```

### 事件里 schema 为空

这个实验已经参考 OpenLineage 的做法，从 `TableLineageDataset.table()` 里拿 `CatalogBaseTable`，再 fallback 到 `getUnresolvedSchema()`。

如果真实生产 connector 仍然 schema 为空，说明该 connector 暴露的信息不够，需要：

- 从 Flink Catalog 补 schema。
- 从 Hive/Paimon/Iceberg/JDBC 元数据补 schema。
- 或者让自定义 connector 实现 Flink lineage 接口。

### 回放任务失败

看诊断接口：

```bash
curl -s -u admin:admin -X POST http://127.0.0.1:8194/tasks/<taskId>/diagnostic
```

常见原因：

- DDL 生成的表名和 SQL 里的表名对不上。
- UDF 没注册。
- watermark / primary key / metadata column 缺失。
- SQL 使用了真实 connector 特性，但回放 DDL 没补对应字段。
